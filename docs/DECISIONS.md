## Combat state model (M3.1-M3.2; M3.3+, the AI layer, session actor and UI build on it)
- `GameState.encounter: Encounter | None` (models/encounter.py) holds the current or LAST fight; it is kept after it ends (status != ACTIVE) for the UI/narrator and replaced by the next start. Creatures stay in `GameState.creatures`; the encounter references them by id.
- `Encounter(id, zone_map, combatants, initiative, round, active_index, turn_open, status)`; `Combatant(creature_id, side, zone_id, economy, xp, withdrawn, surprised)` is the ONE per-participant record: `zone_id` is the position, `economy: TurnEconomy(action, bonus_action, movement_left, reaction, dashed, disengaged)` the BG3 budget, `xp` the kill XP, `withdrawn` fled/surrendered. Sides: PARTY / HOSTILE / NEUTRAL.
- Initiative is rolled once, sorted once (total, DEX score desc, id asc) and never re-sorted; `active_index` -1 before the first turn; `turn_open` separates TurnStarted..TurnEnded.
- Events (models/encounter_events.py, in the `Event` union): EncounterStarted (full snapshot), TurnStarted (index, round, fresh economy), TurnEnded, EconomyChanged (the whole new economy, one event per command), CombatantWithdrew, EncounterEnded (status + XP split, XpGained follow). Applied by session/encounter_apply.py; ReducerError moved to session/reducer_errors.py (still importable from reducer).
- Flow (session drives; rules never apply): start_encounter -> { begin_turn -> commands -> end_turn } with encounter_outcome checked after every applied batch -> end_encounter. begin_turn's economy is computed on a projection of the start-of-turn consequences (ticks, death save) so one TurnStarted carries the final budget.
- Refusals are typed exceptions raised before any event: `EncounterRefused(EncounterRefusal)` (rules/encounter.py), `EconomyRefused(EconomyRefusal)` (rules/turns.py); invalid input never consumes anything.
- Data: monsters come from the SRD registry passed as an argument (`rules/monster_stats.creature_from_monster`); budget tables in data/bg3/encounter_budget.json (`aidm/data/encounter_tables.py`), terrain zone templates in data/bg3/zone_templates.json.

## Spell DSL authoring guide (M3.4; used by M3.5/M3.6 to add spells)
One file per spell: `data/bg3/spells/<srd-index>.json`. The file stem MUST equal `index`, the SRD spell index (data/srd/spells.json). Copy `level`, `school` (SRD school index), `concentration` and the casting time from the SRD entry (tests/unit/data/test_spell_defs.py checks them). Write NO prose: the description comes from the SRD at display time. A spell the DSL cannot express is NOT shipped; list it in docs/RULES_DECISIONS.md (M3.6) instead of approximating it.
- `classes`: SRD class indexes whose lists include it (shipped classes: cleric, fighter, ranger, rogue, warlock, wizard; others are fine to keep).
- `casting_time`: "action" | "bonus_action" | "reaction" (reaction spells are refused until Tier 2; do not ship them) | "minutes" (10 minutes or more: refused in a fight).
- `range`: `{"kind": "self"}`, `{"kind": "touch"}` (same zone) or `{"kind": "feet", "feet": N}` (<= 10 ft same zone, <= 60 ft one hop, more = two hops).
- `duration_rounds`: 1 minute = 10, 10 minutes = 100, 1 hour = 600; required when `concentration` is true; omit for instantaneous spells.
- `targeting.kind`: "self"; "point" (a zone in range, no creature: teleports); "creature" (one target); "creatures" with `count`, `count_per_slot` (extra targets per slot level above the spell's level), `count_by_character_level` (cantrips only, e.g. beams `{"1":1,"5":2,"11":3,"17":4}`) and `repeat` true when several instances may hit the same creature (darts, beams, rays); "area" with `"area": "zone"` or `"zone_and_adjacent"` (cones/lines/spheres from self hit the caster's zone; a ranged area like Fireball targets a zone in range). Area spells hit EVERY other creature there, allies included.
- `effects` (run in order per target): `attack_roll` {attack: melee|ranged, on_hit: [...]}; `save` {ability: str|dex|con|int|wis|cha, on_fail: [...], on_success: "none"|"half"|[...]}; `damage` {dice, damage_type (SRD damage type index), add_modifier, upcast_dice, cantrip_scaling}; `heal` {dice, add_modifier (default true), upcast_dice}; `temp_hp` {dice, add_modifier, upcast_dice}; `apply_condition` {condition (key in data/bg3/conditions.json), rounds (default: duration_rounds), save_ends (ability)}; `remove_condition` {conditions: [...]}; `ac_buff` {condition with ac_bonus, rounds}; `surface` {surface (key in data/bg3/surfaces.json; its harms, durations and interactions live there), rounds}; `hp_pool` {dice, upcast_dice, effects} (with `targeting.order` "hp_ascending"); `stabilize`; `revive` {hp} (with `targeting.dead` true); `teleport` (with a "point" targeting); `multi_target` {area, include_target, effects} (splash around the target).
- Dice: "NdM", "NdM+K"; `upcast_dice` is added once per slot level above the base level; `cantrip_scaling` multiplies the dice count at character levels 5/11/17 (do not use it for beam cantrips, which scale `count_by_character_level`).
- A new condition (e.g. a spell's unique debuff) is a new entry in data/bg3/conditions.json with `srd_condition: false`; use its existing fields (own_attacks, save_disadvantage, speed_factor, ac_bonus, attack_dice, save_dice, ...). Never add code for one spell.
- Each spell needs a golden test `test_golden_spell_<index_with_underscores>` with a ScriptedRng (tests/unit/rules/spell_fixtures.py `caster`, `cast`) and an SRD citation comment.
Example (data/bg3/spells/burning-hands.json):
```json
{"index": "burning-hands", "level": 1, "school": "evocation", "classes": ["sorcerer", "wizard"],
 "casting_time": "action", "range": {"kind": "self"}, "targeting": {"kind": "area", "area": "zone"},
 "effects": [{"type": "save", "ability": "dex", "on_success": "half",
   "on_fail": [{"type": "damage", "dice": "3d6", "damage_type": "fire", "upcast_dice": "1d6"}]}]}
```

## Monster readiness checklist (M3.8; used by M3.9 to pick encounter-ready SRD monsters, CR <= 8)
Run `monster_catalog(REGS.monsters.get(index), REGS.monster_overlay, REGS.spells)` (aidm.rules.monster_catalog) and check:
1. At least one non-spell option exists (`shape` attack, save or multiattack). Monsters with none (frog, rug-of-smothering, sea-horse, shrieker) are NOT ready.
2. If the stat block has a Multiattack action, `catalog.option("multiattack")` exists. A prose-only multiattack lands in `unsupported` as "Multiattack": prefer another monster.
3. `catalog.unsupported` is empty, OR every entry is minor for the monster's role: utility spells ("spell light"), a skipped "ability" part (Frightful Presence), the second breath of a dual-breath dragon whose other breath works. An unsupported signature action (Engulf, Swallow, Petrifying Breath, Possession, Change Shape as its main trick) means NOT ready.
4. Supported action shapes: weapon/natural attacks with to-hit and typed damage (extra damage parts; one-handed choice), attacks with a damage part that has its own DC (poison riders), save actions with damage (breath, cones, lines, "each creature within N ft"; half per data or "half as much damage" in the text), recharge 5-6 / per day / after rest usage, multiattack ("actions" or "action_options" routines of attack steps), legendary actions that are attacks, attack references or damaging saves, spell kits with shipped spells (slots, innate per day, at will).
5. Prose-only riders (paralysis, prone, grapple, poisoned) are NOT executed unless data/bg3/monster_actions.json has an overlay entry (key "<monster>/<action slug>" or "<action slug>"): add one with DSL effects (`on_hit` + `dc`, `on_fail`, `exempt_types`) when the rider matters, else accept the monster as damage-only and note it in RULES_DECISIONS.
6. Mechanical traits that work: Pack Tactics, Nimble Escape, Magic Resistance (data/bg3/features.json); every other special ability is inert. A monster whose identity depends on an inert trait (Regeneration, Incorporeal Movement, Swarm) is ready only as a simplification; say so.
7. One golden test per monster: build it with `srd_monster(index, id)` (tests/unit/rules/monster_fixtures.py), act through `MonsterActionCommand` (`act`) with a `ScriptedRng`, cite the SRD numbers. Baseline: 209 CR <= 8 monsters have an empty `unsupported` list (test_monster_catalog.test_readiness_baseline_cr8).
