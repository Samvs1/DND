# ADDENDUM A: Asset fallback system (binding, part of SPEC.md)

Added after the run started. Fold it into PROGRESS.md as new checkpoints (suggested: A1 inside M7,
A2 and A3 inside M8) and into the M7/M8 exit gates. Do not restart or re-plan anything already done.
This addendum needs NO image API, NO extra keys and NO spending. A separate later goal will add
AI image generation on top of the hooks defined here.

## A.1 Principle
The game never shows a broken image and never blocks on art. Every visual asset is resolved through
one manifest. If the real file is missing, a generated placeholder is shown instead. Replacing a
placeholder with real art must require nothing except dropping a file with the right name.

## A.2 Manifest
`aidm/web/static/assets/manifest.json`, one entry per asset key:

```json
{"portrait.race.tiefling.f": {"kind": "portrait", "file": "img/portraits/tiefling_f.png",
  "size": [512, 512], "transparent": false, "status": "real|placeholder",
  "prompt": "<style-bible-based prompt>", "source": "v1|generated|cc0:<url>", "license": "..."}}
```

Kinds: `portrait` (player and NPC), `monster_token`, `item_icon`, `spell_icon`, `condition_icon`,
`zone_card`, `region_banner`, `music`, `sfx`. Keys are derived from the data registries (classes,
races, monsters, items, spells, conditions, surfaces), so adding a data entry adds a key.
`scripts/build_manifest.py` regenerates the manifest: it marks an entry `real` if the file exists
and `placeholder` otherwise, preserving `prompt`, `source` and `license` of existing entries.

## A.3 Resolution and placeholders
- One function `asset_url(key) -> str` on the server and one `assetUrl(key)` in the frontend are the
  ONLY way UI code references art. No hardcoded image paths elsewhere.
- Missing real files are served by `/assets/placeholder/<kind>/<slug>.svg`, generated by pure
  functions in `aidm/server/placeholders.py`: deterministic from the key (seeded), styled to the dark
  fantasy palette, visibly marked as placeholder (small corner glyph), correct aspect ratio. Examples:
  a portrait silhouette tinted by class with race-dependent features, a monster token as a
  creature-type glyph with CR badge, an item icon by category, a condition icon by name.
- Placeholders are cached and never raise. Unknown keys return a generic placeholder.
- Audio: a missing music or sfx file resolves to silence (no error, no console spam).

## A.4 ASSETS_TODO.md
`scripts/gen_assets_todo.py` writes `ASSETS_TODO.md` in the repo root listing every manifest entry
with `status: placeholder`: key, exact target file path, size, transparency need, and a ready-to-use
image-generation prompt. Prompts come from a short `docs/STYLE_BIBLE.md` that the agent writes by
viewing 3 or 4 of the v1 portraits once and describing the style in words (medium, palette, lighting,
framing, line quality, mood, what to avoid). Every prompt = style bible prefix + subject details
from data (race, class, creature type, material). Never reference BG3 art, characters or any
copyrighted IP in prompts. `--check` mode exits 1 if the TODO file is stale.

## A.5 Gates (add to the existing gate script and to M7/M8 exit criteria)
- `python scripts/build_manifest.py --check` and `python scripts/gen_assets_todo.py --check` exit 0.
- Test: every asset key referenced by data resolves to either an existing file or a valid SVG
  placeholder (parametrised over all classes, SRD races, shipped monsters, items, spells, conditions).
- Test: the frontend contains no hardcoded paths to `/static/img` outside the asset helper
  (grep-style test).
- Test: dropping a file at an entry's `file` path flips it to `real` after `build_manifest.py` and
  `asset_url` serves it, with no other change.
- The Playwright UI test runs once with ALL real art hidden (rename the img folder in a temp copy)
  to prove the game is fully playable on placeholders alone; screenshots in `artifacts/ui/`.

## A.6 Hooks for the later AI generation step (do not build the generator now)
Keep manifest fields `prompt`, `size`, `transparent`, `source`, `license` accurate so a future
`scripts/gen_assets.py` can: read ASSETS_TODO entries, call an image API within a hard budget,
auto-check candidates (size, alpha, blankness), have a reviewer score them against a rubric,
install accepted files under the manifest path and set `source: generated` plus the model name and
license note. Reserve env names `IMAGE_PROVIDER` and `IMAGE_API_KEY` in `.env.example` (names only).

## A.7 Definition of done additions
`ASSETS_TODO.md` and `docs/STYLE_BIBLE.md` exist; README has a short "Adding or replacing art"
section (drop the file named in ASSETS_TODO.md into place, run `build_manifest.py`).
